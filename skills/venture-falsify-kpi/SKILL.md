# 事業證偽與 KPI 路線圖

> 本技能給的是思考框架與檢核表，不是投資、財務或法律建議。所有數字都是「建模假設」，需要你用真實資料驗證。
> 與 `office-hours`、`plan-ceo-review`（gstack）部分重疊；本技能的特色是**台灣法規邊界提示＋KPI 反推鏈＋Phase 0 門檻**。

## 先選模式
| 使用者要什麼 | 走哪一段 |
|---|---|
| 「這生意可不可行／幫我證偽」 | A 證偽 |
| 「營收目標怎麼達成／每天做多少」 | B KPI 反推 |
| 「我要做 App／估開發費」 | C App 構想 |
| 「幫我整合這幾個 AI 的答案」 | D 綜合 |
| 「讓 AI 當老闆的任務書」 | E 任務書檢核 |

## A. 證偽（對抗式檢驗）
1. 去重＋**矛盾清單**（數字、時程、角色前後不一）。
2. 每個模組：真問題 → 付費者 → 價值 → 收益；機會 × 風險表。
3. **戳破樂觀假設**：需求真偽（有沒有人已經付錢）、通路、留存。
4. **單位經濟**：毛利、回本期、規模效應（引用外部經驗法則時標來源）。
5. **法規邊界**：需證照／登記者標紅，轉 `tw-legal-redflag-check`。
6. 一頁結論：**做／不做／縮小做**，各附理由與前提。
7. **Phase 0 驗證**：訪談 10–15 人，至少 3 人願意接受定價才進下一階段（門檻可依事業調整）；寫訪談腳本。
8. MVP：三級資金（最小驗證／小規模／通路擴張）、指標、放棄或改流程的條件。
9. 先現金流、後發展；多個點子要排優先序。

## B. 投資人／股東問題 → KPI 反推路線圖
1. 鎖定範圍與期間；列「確定答案在前」的問題。
2. 標註建模假設（均價、留存、轉換率）——假設要明寫，不得當事實。
3. **反推鏈**：營收目標 → 客戶數 → 成交 → 報價 → 觸及／開發量，再拆成每月、每週、每天。
4. 逐月里程碑、分工表（用職稱不用人名）、護城河與終局、注資觸發條件。
5. 會議紀錄轉「誰要做什麼」行動儀表板。
6. 輸出網頁可用 `premium-report-webpage`。

## C. App 構想 → 開發指南／分期報價
1. 一句話定位＋使用閉環。
2. 技術選型（優先 PWA；不自建模型）。
3. 資料模型／資料表。
4. 第 1 期刻意最小：先讓人願意**每天用**。
5. 分期功能與預算（數字給區間）。
6. 個資與合規風險（涉及記帳、貸款、員工名單等標敏感）。
7. 輸出：開發指南網頁，或給客戶的分期報價提案（架構、甘特、交付物、報價）。

## D. 多 AI 回答綜合
1. 標記各來源。2. 每家定性（學術型／操作型…）並評穿透力與建設性。3. 共識／分歧對照表。4. 依影響力排**前 20%** 關鍵點。5. 萃取各家獨到洞見，合成一條第一原理或公式。6. 可輸出雜誌風網頁。

## E. 給 AI 代理的任務書檢核
補四項：**資金上限與回本期**、**人每週可投入時數**、**風險紅線**、**達標的操作定義**。常見三大漏洞：沒有風險上限（會被推向高槓桿）、前期營收時程與擴張目標矛盾、沒揭露真實資源限制。並問清楚：是另起新事業，還是擴大既有事業線。

## 輸出格式
1. 一句結論（做／不做／縮小做＋理由）。
2. 矛盾與假設清單。
3. 單位經濟表。
4. 法規紅線。
5. 下一步：本週可做的 3 件事＋驗證門檻。

## 常見坑
- 把建模假設寫成事實。
- 沒有「放棄條件」，驗證永遠做不完。
- 評價整合只取平均，不標分歧。
- 輸出帶入真實公司名、合作對象、真實金額（公開範例請用泛化案例）。
