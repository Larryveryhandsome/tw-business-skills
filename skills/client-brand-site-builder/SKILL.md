# 客戶品牌網站一條龍

## 與其他技能的分工
- 報告／SOP 頁 → `premium-report-webpage`。
- 上線前驗收 → 走你自己的上線檢查（可參考本 repo 的 `RELEASE_CHECK.md` 八道閘門）。

## 步驟
1. **收 brief**：品牌名稱、產業、目標客群、主打 3 項、聯絡方式、LOGO、照片、參考網站、改稿意見。缺什麼列清單一次問完。
2. **判斷產業 → 選區塊模板與配色**
   | 產業 | 區塊順序（首屏→頁尾） |
   |---|---|
   | 旅宿 | 首屏大圖＋訂房鈕／房型／周邊／評價／交通／即時通訊常駐鈕 |
   | 餐廳 | 主打菜色／菜單／環境／訂位／地圖 |
   | 診所 | 專科項目／醫師／流程／環境／預約 |
   | 建設／預售 | 建案理念／格局／工法建材／區位／預約賞屋 |
   | 在地小店／個人品牌 | 故事／主打 3 項／社會證明／導航＋聯絡 |
   | 參選人／公共議題 | 理念／政見／行程／志工報名（注意選罷法與廣告規範，交客戶確認） |
3. **問清交付方式**
   - 單檔分享：圖片 base64 內嵌，壓縮到寬約 1000px、品質約 60。
   - GitHub Pages：`images/` 相對路徑。
4. **去 AI 感**：版面空白 40%+、襯線配無襯線、不對稱、少漸層少陰影、動畫慢；配色用**客戶自己的品牌色**（放設定區，見 `config/brand.example.toml`）。
5. **示範稿一律用虛構名稱與虛構資料**；真實客戶資料只放客戶專屬私有版，不進公開 repo。
6. **文字清理**：複製貼上造成的 en-dash、彎引號、全形空白、漏掉的標點掃一遍。
7. **內容規則**：不放會過期的日期；價格／優惠要客戶確認；醫療、建案、政治類不寫誇大或保證字眼（原則上可能涉及廣告相關法規，交客戶或專業人士確認，本技能不是法律意見）。
8. **實測**：用瀏覽器真的打開，檢查圖片載入、手機寬度（約 400px）、電話與通訊連結、頁面無水平捲動。
9. **部署**：GitHub Pages 或 Netlify；回報可點的網址與更新方式。
10. **交付**：附維護方式（誰改文字、多久回覆）。署名位置、價格方案與維護方案放在**私有設定**（`brand.toml` 的 `[pricing]`），不寫進通用模板。

## 輸出
- 網址或單一 HTML 檔、區塊清單、待客戶補件清單、已驗證項目（附檢查結果）。

## 常見坑
- 圖片太大導致單檔數 MB、手機載入慢 → 先壓縮。
- 改稿一句一句進來：每次改完整檔重測，不要只改局部就說好了。
- 示範稿誤用真實店名／電話 → 交付前 grep 一遍。
- 沒測手機版就交件。
